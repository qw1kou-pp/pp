1. 在开始任何 Web 项目之前，先明确你的目标用户是谁，这比选择框架更重要。  
2. Python 的虚拟环境是隔离依赖的利器，推荐使用 `venv` 或 `poetry`，避免全局污染。  
3. FastAPI 凭借异步支持和自动生成的 OpenAPI 文档，已成为现代 Python 后端的热门选择。  
4. 环境变量管理不要硬编码在代码里，使用 `pydantic-settings` 或 `python-dotenv` 来加载 `.env` 文件。  
5. 路由设计应当遵循 RESTful 风格，资源用复数名词，如 `/users` 而不是 `/getUser`。  
6. 数据库迁移工具 Alembic 能帮你跟踪模型变更，记得每次修改模型后生成新的迁移脚本。  
7. 对于关系型数据库，SQLModel 结合了 SQLAlchemy 和 Pydantic，让 ORM 和校验无缝衔接。  
8. 密码存储绝不能用明文，必须使用 `bcrypt` 或 `argon2` 进行哈希加盐处理。  
9. JWT（JSON Web Token）适合无状态认证，但要注意设置合理的过期时间和刷新机制。  
10. 跨域请求（CORS）在开发阶段可以放行所有源，生产环境务必指定白名单域名。  
11. 日志记录不能只用 `print`，应当配置 `logging` 模块，区分 info、warning、error 等级别。  
12. 异常处理要全局捕获，使用 FastAPI 的 `@app.exception_handler` 返回统一格式的错误响应。  
13. 单元测试是项目质量的基石，推荐 `pytest`，配合 `httpx` 的 `AsyncClient` 测试异步接口。  
14. 测试覆盖率至少达到 80%，但不要盲目追求数字，要关注关键业务逻辑的覆盖。  
15. 使用 `pytest-cov` 插件可以生成漂亮的覆盖率报告，直观看到未测试的代码行。  
16. 集成测试时，建议用独立的测试数据库，并在每个测试前后清空数据，保证隔离性。  
17. 对于依赖外部 API 的代码，使用 `responses` 或 `pytest-mock` 来模拟请求，避免网络延迟。  
18. 代码格式化工具 `black` 和 `ruff` 能让团队风格统一，减少 code review 中的无谓争论。  
19. 类型注解不仅让 IDE 更好用，还能通过 `mypy` 静态检查，提前发现潜在的类型错误。  
20. Git 提交信息最好遵循 Conventional Commits 规范，比如 `feat: 添加用户注册接口`。  
21. CI/CD 流水线建议使用 GitHub Actions 或 GitLab CI，自动化运行测试和部署。  
22. Docker 容器化可以保证开发、测试、生产环境的一致性，Dockerfile 要尽量精简层数。  
23. 多阶段构建能显著减小镜像体积，例如先编译依赖，再复制最终产物。  
24. `docker-compose` 适合本地开发，可以一键启动后端、数据库、Redis 和 Nginx。  
25. 生产环境不要用默认的 `uvicorn` 单进程，应当搭配 `gunicorn` 作为进程管理器。  
26. 反向代理推荐 Nginx，它可以处理静态文件、负载均衡和 SSL 终结。  
27. 数据库连接池大小要根据业务并发量调整，过大浪费资源，过小导致请求排队。  
28. 对于慢查询，要开启 SQLAlchemy 的 `echo` 或使用 `slowapi` 中间件来定位瓶颈。  
29. 缓存是性能优化的利器，Redis 适合存储会话、临时数据和频繁读取的配置。  
30. 异步任务（如发送邮件、生成报表）可以用 Celery 或 RQ，配合消息队列 RabbitMQ。  
31. 文件上传要限制大小和类型，并采用流式处理，避免内存爆炸。  
32. 图片处理推荐 `Pillow` 库，可以裁剪、缩放和添加水印，但要注意内存回收。  
33. API 版本控制可以采用 URL 前缀（如 `/v1/`）或请求头，前者更直观易用。  
34. 接口的请求和响应模型应当用 Pydantic 严格定义，过滤掉多余字段。  
35. 对于分页接口，推荐使用 `limit-offset` 或游标分页，后者在数据量大时性能更好。  
36. 全文搜索可以集成 Elasticsearch 或使用 PostgreSQL 的 `tsvector`，根据需求选择。  
37. 数据库索引不是越多越好，要基于查询模式创建联合索引，并定期分析慢查询日志。  
38. 使用 `SQLAlchemy` 的 `selectinload` 预加载关联对象，避免 N+1 查询问题。  
39. 事务处理要保证原子性，可以用 `with session.begin():` 块自动提交或回滚。  
40. 软删除（`deleted_at` 字段）比物理删除更安全，方便数据恢复和审计。  
41. 敏感字段（如手机号、身份证）在日志中应当脱敏，可以使用 `logging.Filter`。  
42. 接口限流可以防止滥用，推荐 `slowapi` 或基于 Redis 的令牌桶算法。  
43. 健康检查端点 `/health` 应返回数据库、缓存等依赖的状态，方便监控系统探测。  
44. 应用启动时可以预加载配置和连接池，减少首次请求的延迟。  
45. 优雅关闭（Graceful Shutdown）能确保正在处理的请求完成后再退出进程。  
46. 使用 `signal` 模块捕获 `SIGTERM` 信号，在容器终止前执行清理工作。  
47. 安全头（如 `X-Content-Type-Options`）可以通过 `SecurityMiddleware` 自动添加。  
48. SQL 注入防范很简单，使用 ORM 的参数化查询即可，不要拼接字符串。  
49. XSS 攻击在前端渲染时处理，后端对用户输入进行校验和转义也有一定帮助。  
50. HTTPS 是生产环境的强制要求，证书可以由 Let's Encrypt 免费获取并自动续期。  
51. 监控和告警推荐 Prometheus + Grafana，可以收集请求数、错误率、响应时间等指标。  
52. 错误追踪可以使用 Sentry，它能捕获未处理异常并附上堆栈和环境信息。  
53. 性能分析工具 `py-spy` 或 `async-profiler` 可以在不重启的情况下采样 CPU 使用。  
54. 数据库备份策略至少为每日全量 + 实时增量，并定期演练恢复流程。  
55. 部署时不要使用 `root` 用户运行应用，应创建普通用户，降低安全风险。  
56. 配置文件应当区分开发、测试、生产环境，但敏感信息只从环境变量读取。  
57. 项目结构推荐按功能划分，比如 `app/api/`, `app/core/`, `app/models/`, `app/services/`。  
58. 依赖管理锁定版本号（如 `fastapi==0.115.0`），避免自动更新带来的不兼容。  
59. 使用 `pre-commit` 钩子在提交前自动运行格式化、类型检查和简单测试。  
60. 代码评审时不仅要看逻辑，还要关注性能、安全性和可维护性。  
61. 文档不止于 OpenAPI，还应有架构设计说明和部署手册，方便团队交接。  
62. 用户注册后发送验证邮件，可以使用 `itsdangerous` 生成带时效的链接。  
63. 重置密码流程应包含令牌校验，且令牌只能使用一次，过期后自动作废。  
64. 多语言支持（i18n）可以通过 `babel` 提取翻译字符串，根据请求头返回对应语言。  
65. 对于长耗时操作，采用 WebSocket 或 Server-Sent Events 推送进度，而不是轮询。  
66. 数据库字符集统一使用 `utf8mb4`，以支持表情符号和特殊字符。  
67. 时间存储推荐 UTC 标准时，显示时再转换为用户本地时区。  
68. 使用 `uuid` 作为主键比自增整数更安全，尤其在分布式系统中避免冲突。  
69. 列表查询时允许排序、过滤和搜索，但参数过多时要防止恶意构造巨大查询。  
70. 后台管理界面（如 Admin）可以使用 `sqladmin` 或集成 Django Admin，但需权限控制。  
71. 接口返回的数据最好包装成统一格式，比如 `{code, data, message}`。  
72. 错误码设计要有层次，例如 4000 表示参数错误，4001 表示用户不存在。  
73. 对于第三方回调，要验证签名并实现幂等性，防止重复处理。  
74. Webhook 重试机制必不可少，可以设置指数退避，避免瞬间打垮下游服务。  
75. 使用 `httpx` 替代 `requests`，因为它支持异步和 HTTP/2，性能更好。  
76. 服务间通信可以采用 gRPC 或 REST，前者效率高，后者更通用。  
77. 对于大量数据导出，采用流式 CSV 或分页 JSON，不要一次性加载到内存。  
78. 导入数据时，使用批量插入（`bulk_insert_mappings`）能大幅提升速度。  
79. 定时任务可以用 `apscheduler` 或 `celery beat`，但要注意避免重复执行。  
80. 使用 `python-multipart` 解析表单数据，支持文件流和混合参数。  
81. 中间件执行顺序很重要，日志中间件应当靠近入口，认证中间件紧跟其后。  
82. 单元测试中，使用 `pytest.fixture` 复用数据库会话和客户端实例。  
83. 测试时可以用 `freezegun` 冻结时间，确保依赖时间的逻辑稳定。  
84. Mock 外部 API 时，要模拟各种状态码和超时场景，增强代码健壮性。  
85. 性能压测工具 `locust` 可以模拟高并发，帮你找到系统的瓶颈点。  
86. 内存泄漏排查工具 `tracemalloc` 能跟踪对象分配，定位未释放资源。  
87. 日志轮转（log rotation）使用 `RotatingFileHandler` 或 `TimedRotatingFileHandler`。  
88. 开发环境建议使用 `--reload` 热加载，但生产环境务必关闭。  
89. 端口映射在 Docker 中要显式指定，避免与宿主机端口冲突。  
90. 网络模式建议使用自定义桥接网络，便于服务发现和隔离。  
91. 持久化数据（如数据库文件）要挂载卷（volume），防止容器重启丢失。  
92. 使用 `.dockerignore` 忽略不必要的文件，加快构建速度。  
93. 镜像标签最好包含版本号或 Git commit hash，方便回滚追溯。  
94. 部署到云服务器时，安全组规则只开放必要端口（如 80、443）。  
95. 使用 `systemd` 或 `supervisor` 管理应用进程，确保崩溃后自动重启。  
96. 日志聚合可以使用 ELK（Elasticsearch, Logstash, Kibana）或 Loki。  
97. 分布式追踪（如 Jaeger）能帮助梳理微服务间的调用链路。  
98. 数据库读写分离可以提升并发能力，但需处理主从延迟问题。  
99. 定期清理过期的会话和临时文件，避免磁盘占满。  
100. 最后一条建议：保持学习，关注社区动态，但不要盲目跟风，选择适合自己项目的方案。
